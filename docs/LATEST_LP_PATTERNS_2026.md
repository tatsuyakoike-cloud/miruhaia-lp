# 2026年時点のLP設計パターン

調査日：2026-07-22。以下は公開資料をコピーしたものではなく、公式仕様とUX調査からミルハイア向けに再構成した設計ルールです。

## 1. スマホを簡易版にしない

Googleはモバイル版を基準にクロール・インデックスし、同じ主要コンテンツとメタデータを推奨しています。重要情報をタップやスワイプ後にしか読み込まない構成も避けます。

適用：スマホでも料金・サービス・FAQ・動画の意味を保ち、表示密度だけを変えます。

## 2. 読み込ませるより、読み飛ばして理解させる

Web利用者は文章を精読するよりスキャンする傾向があります。

適用：1セクション1結論、短い見出し、カードは最大3要素を目安にし、動画品質と3プランを視覚中心で示します。

## 3. 中小企業向けは「安心材料」を前倒しする

これは調査からの設計上の解釈です。SNSに詳しくない読者は、派手さより「何をする・どの品質・いくら・誰が進める・どう始まる」が早く分かる方が判断しやすくなります。

適用：解決策の直後に動画3本を置き、支援範囲と料金を早めに提示します。偽の受賞歴・曖昧なNo.1・過剰なカウントアップは使いません。

## 4. 縦動画は自動再生より選んで見られる形

適用：ポスターを先に見せ、利用者が再生します。PC3列、SPは1本ずつ。3本すべての先読みを避け、表示速度と通信量を守ります。

## 5. 表示速度をデザイン要件にする

現在のCore Web Vitalsの良好基準はLCP 2.5秒以内、INP 200ms以内、CLS 0.1以内です。

適用：ヒーロー画像の優先読込、画像・動画の寸法予約、不要なJSと外部ライブラリの削減、フォントの最適化を行います。

## 6. 操作の分かりやすさを信頼感につなげる

適用：44px以上のタップ領域、明確なフォーカス、キーボード操作、reduced-motion、色だけに頼らない表示を行います。

## 7. Agentへの指示を1ファイルへ詰め込みすぎない

Cursorの現行仕様では、常時ルールは`.cursor/rules/*.mdc`、再利用ワークフローは`.cursor/skills/*/SKILL.md`へ分けられます。

適用：本キットは`CLAUDE.md`を統合仕様としつつ、Cursor側は短いルールと段階的に読むSkill／referencesへ分離しています。

## 8. 公開工程まで実装に含める

Viteはビルド工程が必要なため、GitHub PagesではActionsによる公開とリポジトリ名に応じた`base`設定を行います。
